GemOS

Desktop OS, from the boot sector up.

A from-scratch 32-bit x86 operating system with its own bootloader, kernel, GUI stack, filesystem, scheduler, Ring 3 path and userland MVP.

Status

What works right now

Boot chain

Stage 1 + Stage 2, A20, GDT, protected mode, kernel entry.

Execution core

IDT, IRQ/ISR, PIC, PIT, RTC, serial debug, scheduler, heap, paging MVP.

Desktop stack

VBE LFB, page-flipped rendering, WM, topbar, dock, menus, TTF text.

Storage

ATA PIO and GemFS with working kernel-space apps.

Isolation

Ring 3, per-process CR3, TSS, `esp0`, faulted user process cleanup.

Userland MVP

ELF32 static loader, `int 0x80`, minimal syscalls, first real terminal path.

Architecture

Layered on purpose

Syscalls and console service
Scheduler, process model, ELF loader
Paging, heap, interrupts, timer
VBE, PS/2, ATA, serial, RTC
Bootloader stage1 + stage2

Principles

No fake complexity

  • System, not demo
  • Architecture before features
  • Small steps over grand rewrites
  • Own the whole stack
  • Only generalize APIs after real use proves it

Milestones

Interactive roadmap

GemOS owns the boot process and kernel infrastructure instead of leaning on GRUB or a hosted runtime.

The desktop stack is already usable: windows, dragging, focus, menu flow, dock, fonts, storage-backed apps.

The current transition phase is about turning working isolation into practical userspace through thin, stable services.
